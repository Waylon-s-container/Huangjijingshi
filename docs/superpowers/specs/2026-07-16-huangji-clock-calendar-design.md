# 皇极经世书时钟日历 · 设计文档

> 创建日期：2026-07-16
> 状态：已确认，待转入实现计划

## 一、定位

**可视化探索皇极经世时间哲学体系的单页 Web 应用。**

以卦象为导向，三层尺度（会/运宏观 → 值年中观 → 日卦微观）层层下钻，让人直观漫游邵雍元会运世的宏大时间结构。无后端、无数据库，所有计算在浏览器端完成。

核心理念：人的一生在元会运世的尺度下只是一个点。本应用让用户能"站在卦象里"感受时间的纵深，而非做一个干巴巴的换算工具。

## 二、三层尺度与交付计划

采用**分三层递进**的交付策略。每层交付时都是可独立使用的产物，最后串联成完整体验。

| 阶段 | 层 | 主视觉 | 时间轴尺度 | 交付目标 |
|------|-----|--------|-----------|---------|
| **P1** | 中观 · 值年卦 | 64卦圆图，当前年朱砂+墨晕高亮 | 年级（漫游任意年份） | 核心体验跑通 |
| **P2** | 宏观 · 会/运 | 十二消息卦嵌套圈 | 万年级 | 宏观结构可见 |
| **P3** | 微观 · 日卦 | 日卦月历 | 日级 | 日常可用 |
| **串联** | 三层联动 | 尺度切换器激活，下钻/上卷 | 时间轴随尺度变化 | 完整体验 |

**导航逻辑**：宏观 ↕ 中观 ↕ 微观，层层下钻/上卷。用户可在任意尺度停留、漫游，也可点击下钻进入更细的尺度，或上卷回到更大的尺度。

## 四、核心算法（追求学术准确）

> ⚠️ **修订说明**：初版以"尧元年=元之始"作起算点，与首屏"午会"定位存在算术矛盾（4382年<6×10800年，不可能到午会）。经查证多来源确认，邵雍通行说法是**"尧≈午会之始"**，一元起于约公元前 67017 年。本节据此重写。

### 4.1 起算点

- **采用**：一元之初 = 公元前 67017 年（反推自邵雍所标历史事件），通行说
- **尧元年（公元前 2357 年，甲辰）** 作为**人事纪年起始点**，落在午会开端附近（午会约公元前 2217 — 公元 8583）
- 依据：知乎专栏《元的时间起点如何推演》、维基百科、百度百科交叉一致
- 这样才能产生"午会"这一标志性定位（午会为第7会，需 6×10800=64800 年累积）

### 4.2 元会运世换算

纯算术换算，有唯一正确解：

```
1元 = 12会 = 129600年
1会 = 30运 = 10800年
1运 = 12世 = 360年
1世 = 30年
```

**关键：无公元 0 年的处理。** 公元前 A 年到公元后 B 年的年数 = A + B − 1（不是 A + B）。实现时显式拆分符号，勿用 `year − (−N)` 隐式形式：

```javascript
// 一元之初为公元前 67017 年（即 year = -67017）
// 距一元之初的年数（含无公元0年校正）
function yearsSinceEpoch(year) {
  // 前 A 年到后 B 年 = A + B - 1；前 A 年到前 C 年 = A - C
  if (year > 0) {
    return 67017 + year - 1;   // 前67017到公元year
  } else {
    return 67017 - (-year);    // 前67017到公元前year
  }
}

// 回归校验：yearsSinceEpoch(-67017) === 0  ✓
//          yearsSinceEpoch(-2357)  === 64660 ✓（尧元年距元初）
//          yearsSinceEpoch(2026)   === 69042 ✓
```

分层取值：
```
gregorianToHuangji(year) → { yuan, hui, yun, shi, yearInShi }
  1. total = yearsSinceEpoch(year)
  2. yuan  = floor(total / 129600)      // 当前为第 yuan+1 元
  3. rem1  = total % 129600
  4. hui   = floor(rem1 / 10800)         // 当前为第 hui+1 会（0=子…6=午）
  5. rem2  = rem1 % 10800
  6. yun   = floor(rem2 / 360)           // 会内第 yun+1 运（全元第 hui*30+yun+1 运）
  7. rem3  = rem2 % 360
  8. shi   = floor(rem3 / 30)            // 运内第 shi+1 世
  9. yearInShi = rem3 % 30               // 世内第 yearInShi+1 年
```

### 4.3 多层卦象体系

> **修订说明**：经查证，皇极经世实际有多层卦象，不止"值年卦"一层。任一时刻的完整定位含 5 层卦。这影响原设计的"三层尺度"划分——需重新厘清。

**完整卦象层次（任一时刻）：**

| 层 | 主事周期 | 卦象 | 2026年实例 |
|----|---------|------|-----------|
| 会卦 | 10800年 | 午会正卦 | 大过 |
| 运卦 | 360年 | 当前运卦 | 姤（天风姤） |
| 世卦 | 30年 | 当前世卦 | 鼎 |
| 旬卦 | 10年 | 当前十年卦 | 姤 |

| 项目层 | 对应卦象层 | 说明 |

### 4.4 卦象配法

皇极经世卦象配法存在多家之说（康节原文、朱熹后学、近人张行成、王植、张其成等整理）。本项目策略：

- **选定一套自洽方案**作为默认，明确标注出处
- **模块化实现**，后续可切换不同流派的配卦法
- **不伪装配法为唯一正解**

各层配法（具体采用哪套流派方案，在各阶段实现时查文献选定并在代码与页脚标注）：

| 层 | 配法框架 | 关键规则 | 实现时选定 |
|----|---------|---------|-----------|
| 值年卦（P1） | **去四正卦60甲子配卦法** | 去乾坤坎离四正卦（统领/闰卦），余60卦按先天圆图顺时针配60甲子；每花甲以世卦为起卦；60年一轮，与360年/运天然整除 | 查文献选定基准年与起卦规则，标注出处 |
| 会卦（P2） | 十二会对应主卦 | 午会=大过等 | 标注出处 |
| 运卦/世卦/旬卦（P2） | 多级推演 | 见各文献 | 标注出处 |
| 日卦（P3） | 基于值年卦 + 月日推演 | — | 标注出处 |

> **视觉与配法分离**：主图仍用完整64卦圆图（更美、更全），但四正卦在配法上是"统领卦/闰卦"、不参与值年。这点在 UI 上需说明，避免实现困惑。

## 六、技术风险与降级方案

### 6.1 水墨写意渲染（高风险）

"毛笔写意——墨色浓淡、枯笔飞白"在 Canvas 里是高难度效果，`InkBrush.js` 是共享给三层渲染的核心模块。若达不到预期，三层视觉都会受影响。

**风险处理：P1 启动前做技术 spike。**
- 用 1-2 个卦（如坤、既济）验证枯笔/浓淡能否达到"模拟真实毛笔"的最低要求
- spike 通过 → 按原方案推进
- spike 不达标 → 启用降级备选：
  - **备选 A**：预渲染水墨笔触贴图（SVG/位图），运行时按笔画拼贴
  - **备选 B**：SVG filter（`feTurbulence` + `feDisplacementMap`）模拟墨晕渗化
  - **备选 C**：退回工笔规整风格，接受视觉降级

技术风险标记为 P1 首要验证项，不视为已解决问题。

### 8.2 状态管理

零构建约束下不引入框架。采用**发布-订阅模式 + 单一 state 对象**：

```javascript
// store.js
const state = {
  year: 2026,        // 当前选定年份
  scale: 'year',     // 当前尺度：'era' | 'year' | 'day'
  hexagram: null,    // 当前高亮卦象
  // ...
};
const listeners = [];
function subscribe(fn) { listeners.push(fn); }
function setState(patch) { Object.assign(state, patch); listeners.forEach(fn => fn(state)); }
```

各渲染模块 `subscribe` 状态变化，用户交互（时间轴拖动、点击卦象、切换尺度）通过 `setState` 触发重绘。单一 state 保证多尺度联动时状态一致。

### 8.3 64卦数据来源与版权

`hexagrams.js` 需装入全量卦象数据（卦名、卦辞、爻辞、阴阳爻）。底本与版权确定：

- **底本**：采用公有领域的经典底本（《周易》通行本，卦辞爻辞为两千年前古籍，无版权争议）
- **数字化来源**：优先采用 CC-BY 或公有领域的数据集（如 ctext.org 中国哲学书电子化计划的开放数据）；若使用第三方整理数据，在 README 标注来源与许可
- **注释/白话译文**（若有）：避免直接搬运受版权保护的今人译注，自行编写或采用公有领域译本

### 10.2 算法回归用例（量化基准）

| 输入（公历） | 期望输出 | 校验点 |
